## H1 Правила функции

Что функция принимает, возвращает и проверяет: Процедура clean_export(source) обрабатывает исходный датасет и возвращает структуру из трех объектов: clean, quarantine и audit.
clean — отфильтрованный слой: избыточные дублирующиеся строки исключаются и фиксируются в replays, региональный код county_code очищается посредством метода str.strip(), финансовые и категориальные признаки (source_row, action_taken, loan_amount, income) приводятся к числовому формату, при этом показатель income может содержать неопределенные значения NaN. В итоговый массив clean зачисляются исключительно записи с корректным ключом source_row, статусом решения action_taken из набора {1, 2, 3}, строго положительной и определенной величиной займа loan_amount > 0 и нормализованной территорией county_code после выполнения операции strip(), равной "11001".
• quarantine — массив сырых строк, нарушивших установленные бизнес-правила, дополненный техническим столбцом reason со списком ошибок (некорректный source_row, некорректный action_taken, некорректная сумма кредита, некорректная территория, некорректный доход). Записи-дубликаты сюда не включаются. При обнаружении противоречивых содержательных версий для одинакового первичного ключа source_row работа алгоритма аварийно прерывается через assert.
• audit — отчетный лог, содержащий метрики input, replays, clean, quarantine и parse_errors.
Баланс: input == replays + clean + quarantine.

## H3 Проверка года и виды проблем

В тестовом датафрейме wrong_year у начальной строки значение activity_year принудительно заменяется на "2022". Встроенное выражение проверки eq("2023\").fillna(False).all() возвращает логическое значение False — несоответствие оперативно перехвачено. Функция .fillna(False) интерпретирует любые скрытые или пустые значения отчетного периода как ошибку валидации и блокирует пропуск некорректных строк, при этом оригинальный массив export защищен от изменений.
Три вида проблем:
1. Исходный пропуск — в строке с source_row = 99 признак income не заполнен. Логика пайплайна: строка признается валидной и сохраняется в датасете clean, значение поля принимает формат NaN, замена пропусков искусственными нулями не производится.
2. Ошибка преобразования — в записи с source_row = 2 обнаружен некорректный текстовый шум в финансовом показателе (loan_amount = \"oops\"), а в строке source_row = 5 — строковая аномалия в поле заработка (income = \"BAD\"). Логика пайплайна: данные строки отсеиваются в датасет quarantine с фиксацией меток некорректная сумма кредита / некорректный доход, при этом счетчик parse_errors растёт.
3. Необычно большая сумма — в строке с source_row = 326 указана величина займа loan_amount = 57005000.0. Это значение является физически корректным числом, поэтому логические фильтры его не удаляют. Для проведения экспертной ручной проверки и поиска статистических выбросов такие крупные операции отбираются отдельно (loan_amount > 5_000_000) для смыслового просмотра.
